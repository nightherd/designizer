Strata
How it works Commands GitHub

Change your schema one layer at a time.

Strata is a command-line tool for database migrations. You write plain SQL files, Strata applies them in order, records what ran, and warns you before anything locks a busy table.

brew install strata

Or download a single binary for macOS, Linux or Windows. Works with Postgres, MySQL and SQLite.

Every change is a file you can read

      
No DSL and no generated code. A migration is a SQL file with an up half and a down half, named so the order is obvious in any file listing.

      

        
    
          
  1. 
            
    Write it
    
            
    strata new add_accounts_timezone creates a numbered file with both halves ready to fill in.
    
          
    2. 
          
  2. 
            
    Plan it
    
            
    strata plan shows the exact statements that will run and which ones take locks, before you touch the database.
    
          
    3. 
          
  3. 
            
    Apply it
    
            
    strata up runs each pending file in its own transaction and records a checksum, so edited history gets caught later.
    
          
    4. 
          
  4. 
            
    Undo it if you need to
    
            
    strata down runs the down half of the most recent migration. Add --steps 3 to go further back.
    
          
    5. 
        

        

          
migrations/0006_add_accounts_timezone.sql


-- strata:up
ALTER TABLE accounts
  ADD COLUMN timezone text
  NOT NULL DEFAULT 'UTC';

CREATE INDEX CONCURRENTLY accounts_timezone_idx
  ON accounts (timezone);

-- strata:down
DROP INDEX accounts_timezone_idx;
ALTER TABLE accounts DROP COLUMN timezone;

        

      

    

  


  

    

      

        
Know what locks before it locks

        
Strata reads each statement and tells you how it will behave on your database version. A column with a default is instant on Postgres 11 and later. An index built without CONCURRENTLY blocks writes until it finishes. You find out at your desk, not during the deploy.

      


$ strata plan
Target: acme_production (Postgres 16.2)
Pending: 3 migrations

0006_add_accounts_timezone
  ok    ADD COLUMN with constant default
  ok    CREATE INDEX CONCURRENTLY
        runs outside a transaction

0007_backfill_timezone
  warn  UPDATE without WHERE touches
        ~4.2M rows in accounts

0008_drop_legacy_sessions
  warn  DROP TABLE takes an ACCESS
        EXCLUSIVE lock on legacy_sessions

Run strata up to apply, or
strata up --to 0006 to stop early.

    

  


  

    

      
Small tool, careful defaults

      
Strata does one job. It doesn't need an ORM, a runtime or a config server.

      

        
One binary
About 9 MB with no dependencies. Drop it into a CI image or a container and run it.

        
Transactions by default
Each migration commits or rolls back on its own. A failure halfway leaves your schema at the last good version.

        
Checksums on history
If someone edits a migration that already ran, strata verify fails and names the file.

        
A lock that prevents races
Two deploys starting at once can't both migrate. The second one waits, then sees there's nothing left to do.

        
Readable state
History lives in a strata_history table you can query with any SQL client.

        
Bring your own layout
Point it at any folder with --dir or a two-line strata.toml. Existing numbered files work as they are.

      

    

  


  

    

      
The whole interface

      
There are six commands. Run strata help <command> for flags.

      

        
CommandWhat it does

        
          
strata new <name>Creates the next numbered migration file with empty up and down sections.

          
strata planLists pending migrations and flags statements that lock tables or rewrite many rows.

          
strata up [--to <version>]Applies pending migrations in order, stopping at a version if you give one.

          
strata down [--steps <n>]Rolls back the most recent migration, or the last n.

          
strata statusShows the current version and which files are applied, pending or modified.

          
strata verifyCompares checksums of applied files with what's on disk. Exits non-zero on a mismatch.

        
      

    

  


  

    

      
Install Strata and run your first migration

      
Set DATABASE_URL, run strata new, then strata up. That's the whole setup.

      

        curl -fsSL https://strata.sh/install | sh
